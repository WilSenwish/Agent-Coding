# 审计与报告模板

三份报告跨三个阶段节点：`audit-baseline.md`（人工关卡 A）、`exploration-options.md`（人工关卡 B）、`spec-coverage-report.md`（E4 自动核对，无人工关卡）。三者共同构成漂移拦截网。

### 5. 结论

```markdown
- 未覆盖：<n> 项（列 ID）
- 脑补：<n> 项（列 ID）

```

> 判定为 ❌ 时，**不得进入阶段2**。回流不是失败，是这一轮澄清的正常产出。

## 二、exploration-options.md（OPEN 项决策单，关卡 B 用）

> 人工在这里做批量决策，**这是唯一处理未知的窗口**。决策前不得写实现代码。

```markdown
### OPEN-01 未支付订单能否取消
- 现象：产品未回答；存量代码允许取消但无退款校验
- 影响面：IMP-01（接口）、IMP-03（Service）、IMP-07（状态机）
- 方案 A：允许取消，无退款流程
  - 接口：无变更
  - 单测：+2 用例（未支付取消、幂等）
  - 集成：+1 用例（无退款记录断言）
  - 风险：低
- 方案 B：禁止取消，返回 E_STATUS_NOT_ALLOWED
  - 接口：新增错误码
  - 单测：+1 用例
  - 集成：+1 用例
  - 风险：低；但可能与存量行为不符，需回归
- 推荐：A（保持存量行为，不扩大本次改动）
- 决策： ☐ 采纳A  ☐ 采纳B  ☐ 延后(→OUT_OF_SCOPE)  ☐ 维持存量
```

决策后的动作（Agent 执行）：

| 决策 | 后续 |
|---|---|
| 采纳方案 | 将该条并入 `baseline-spec.md` SETTLED，升版本，重生成 plan/清单，再进关卡 B |
| 延后 | 移入 OUT_OF_SCOPE，plan 中剔除，不生成测试 |
| 维持存量 | 写入基线"存量行为冻结"条目，测试仅做回归保护 |

## 机械校验（可选）

```bash
python3 scripts/check_spec_coverage.py <项目根目录> \
  --baseline baseline-spec.md \
  --scan plan.md src/test src/main \
  --require-impact
```

输出每个 SPEC-ID 的引用位置、未被引用的清单；`--require-impact` 额外检查 SPEC 是否绑定了 IMP。退出码 1 表示存在未覆盖项，可用于本地自检（不接 CI，仅手动执行）。
